The problem

Agents start every task knowing nothing about where they work.

The answer to most questions already exists somewhere in the company. What's missing is a safe, consistent way for agents to reach it.

Context-starved

Agents don't know how the company is organized or what it already knows. They guess, or people paste the same background in again and again.

Over-privileged

Once an agent is wired to real systems, it often sees whatever the integration's service account sees. Nobody decided that; it just happened.

Rebuilt in every team

Connectors, retrieval and the useful tools agents write get rebuilt by each team, because nobody can see that the next team over already made them.

Product

One system for what agents know, remember and reuse.

Retrieval, memory, requests and tools live together, so an agent can find the source, see what the team decided, ask a person, and pick up a tool a colleague's agent already wrote.

Cited knowledge

Running today

Searches return ranked source passages, not paraphrase: the page range of a PDF, the heading and paragraph of a document, or the minute and second of a recording.

Converts anything

Running today

PDFs (with OCR and text repair), Word, HTML, Markdown and EPUB, plus audio and video, transcribed and indexed, including text shown on screen.

Shared project memory

Running today

Each project keeps a short, revisioned memory that every agent reads at the start of a session and keeps current: decisions, conventions, who owns what.

Requests between people and agents

Running today

Bugs, features, questions, tasks and access requests go to a person, an agent, a team or a resource's owners, in threads that keep every message.

Captured tools

Running today

When an agent builds a script, CLI or MCP server, Witwell files it with its versions, manifest and checksums. A teammate's agent can find it and use it the next day.

MCP-native

Running today

Three MCP servers expose more than sixty tools, packaged with install guides for the common agent clients on Windows, macOS and Linux.

Organization and teams

Enterprise preview

Nested teams, matrix structures, people and a sharing matrix that decides which tier sees which knowledge base and tool.

Audit trail

Enterprise preview

A searchable record of who and which agent read or changed what, with filters and export.

Questions

Frequently asked

Is Witwell available today?

The Witwell core runs in production today. The Enterprise edition is in preview with design partners, and the open-source edition will be published at github.com/witwell. Each capability on this page shows its current status.

Which agents work with Witwell?

Any agent client that speaks the Model Context Protocol. Witwell ships an install package with instructions for the common coding agents and desktop assistants on Windows, macOS and Linux.

Does our data leave our environment?

No. Witwell is self-hosted and runs its models locally by default, so documents, recordings and indexes stay on your servers. Using an external model provider would be an explicit choice you make, not a default.

Is this enterprise search with a chat window?

No. Witwell is built for agents: it returns cited source passages for an agent to work from, and adds what search tools lack, a shared memory, requests between people and agents, and a home for the tools agents build, all governed by the same organizational tiers.

How does Witwell decide what an agent can see?

Knowledge, tools and memory belong to tiers of the organization. A person's agent inherits the tiers that person belongs to and nothing else. The data layer already enforces isolation with row-level security on every row. The Enterprise edition, now in preview, adds teams, the sharing matrix and the audit trail; single sign-on, which ties each agent to its signed-in person, is in alpha.

What does it cost?

The open-source edition is free under Apache-2.0. Enterprise pricing will be set with our design partners; talk to us about your scale.
